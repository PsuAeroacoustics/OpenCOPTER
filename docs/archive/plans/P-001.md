## 1. Goal

Expose the per-rotor **hub-moment coefficients** `C_Mx` (roll, blade-element x-moment) and
`C_My` (pitch, blade-element y-moment) as **read-only getters** in the two public APIs that
are missing them:

- **C API** — `include/opencopter.h` (declaration) + `source/opencopter/cbindings.d` (implementation).
- **C++ API** — `include/opencopter.hpp` (declaration) + `source/opencopter/cppbindings.cpp` (implementation).

Expose at the **`RotorState` level only**, matching the existing `C_T`/`C_Q` getters. Include tests.

## 2. Rationale & gap

The values already exist and are maintained by the D core:

- Stored: `RotorStateT.C_Mx`, `RotorStateT.C_My` — `source/opencopter/aircraft/state.d:186-187`.
- Zeroed + accumulated per blade each step: `source/opencopter/bladeelement.d:363-364` (reset), `:472-473` (accumulate `rotor_frame_moments[0]` → `C_Mx`, `[1]` → `C_My`).

But they are **not** reached through the C / C++ public surface. Today they are only:
- read in D by `validation/HART_II/main.d:1149-1150`, and
- exposed via the **Python** API (`source/opencopter/python.d:2567-2568` — "current x/y moment coefficient of this rotor").

So C and C++ are the two gaps. **Hub moments** = `C_Mx` + `C_My`. The moment about z (hub
**torque**) is `C_Q`, already exposed — do **not** add a `C_Mz` (no such field in `RotorStateT`).

## 3. Scope decisions (user-locked)

| Decision | Value |
|---|---|
| Level | **`RotorState`-level only** (no `oc_aircraft_state_get_rotor_C_Mx` / `AircraftState::rotor_C_Mx(i)`). RotorState reachable via `oc_aircraft_state_get_rotor_state(state, i)` / `AircraftState::get_rotor_states().at(i)`. |
| Direction | **Getters only** (no setters — computed outputs, not inputs). |
| Tests | **Yes** — C-level (`tests/src/test_api_aircraftstate.cpp`) + C++-level (`tests/src/test_cpp_api.cpp`). |
| D core | **Untouched** — data already exists. *(Refined in S2: a 4-line ctor zeroing was added to `state.d` `RotorStateT` to fix a NaN-before-first-step bug the S2 test exposed — see §12 deviation note.)* |

## 4. Architecture (where the 4 pieces fit)

```
                opencopter.hpp (C++ decl)  ──  RotorState::get_C_Mx/C_My()
                       │
   cppbindings.cpp     │   (void* → OC_RotorState*, calls oc_*)
                       ▼
   oc_rotor_state_get_C_Mx / oc_rotor_state_get_C_My   (C ABI symbols)
   opencopter.h (C decl)
                       ▲
   cbindings.d         │   (cast OC_RotorState* → D RotorState*, read .C_Mx/.C_My)
                       │
   RotorStateT (D)     └─  .C_Mx, .C_My  (state.d:186-187)  ← already computed (bladeelement.d:472-473)
```

C impl is **D** (`extern(C)`); C++ impl down-casts the opaque `void*` to `OC_RotorState*` (via
`rst(*this)`) and calls the C function, returning `double` and degrading to `0.0` on a null
wrapper (consistent with `get_C_T`/`get_C_Q`).

## 5. Naming (follow existing convention exactly)

C scalar getters return via `double* result_out`, null-guarded (matches `oc_rotor_state_get_C_T`):
```c
void oc_rotor_state_get_C_Mx(const OC_RotorState* state, double* result_out);
void oc_rotor_state_get_C_My(const OC_RotorState* state, double* result_out);
```
C++ methods mirror `RotorState::get_C_T() const`:
```cpp
double get_C_Mx() const;
double get_C_My() const;
```

## 7. Testing strategy

Both layers get a C-level test (primary) and a C++-level test.

- **C level** — `tests/src/test_api_aircraftstate.cpp`. There is **no setter** for `C_Mx`/`C_My`
  (computed, not assigned), so — unlike the `C_T`/`C_Q` round-trip at lines 174-182 — assert:
  the getters **write to the out-pointer** (seed `1e9`, confirm overwritten to finite — defeats
  the "didn't write" failure mode), both **finite** and `== 0.0` (D POD default before any step),
  and **null-safety** (`oc_rotor_state_get_C_Mx(nullptr, nullptr)` doesn't crash — mirrors
  `AircraftState.RotorCTNullSafe` at line 27). Reuse the `oc_aircraft_state_create(...)` setup of
  `AircraftState.RotorStateCTSetGet` (lines ~133-201).
- **C++ level** — `tests/src/test_cpp_api.cpp`. A default-constructed `RotorState` is a null
  wrapper (`cppbindings.cpp:757` pattern → returns `0.0`) — the cheap, high-value case. A positive
  case needs a **fully** constructed `AircraftState` (see `opencopter.hpp:790-800`) — mark as
  `stretch`: reuse the `test_api_aircraftstate.cpp:133-201` construction recipe, then wrap.

## 9. Risk & safety

- **Non-breaking:** purely additive; no existing symbols change.
- **No physics change:** D core untouched; we only read computed fields.
- **Null-safety is contractual:** C functions null-guard `state` and `result_out`; C++ getter
  returns `0.0` on a null wrapper.
- **Zero-default assumption:** asserting `C_Mx == 0.0` before any physics step relies on the
  `RotorStateT` ctors zeroing the field. The S2 test proved this assumption was **wrong** — the
  ctors only zeroed `C_T`, leaving `C_Q/C_Mx/C_My` NaN (uninitialized). Fixed by adding `C_Q = 0;
  C_Mx = 0; C_My = 0;` to both `RotorStateT` ctors (`state.d:195-214`), mirroring the existing
  `C_T = 0` and the `compute_rotor_properties` reset (`bladeelement.d:363-364`). The seed-overwrite
  check still proves the write path. This is the one non-test change in the plan (user-approved).

## 10. Out of scope (deferred)

- Setters `set_C_Mx` / `set_C_My` — not requested.
- Aircraft-indexed getters `oc_aircraft_state_get_rotor_C_Mx/C_My` + `AircraftState::rotor_C_Mx/C_My(i)` — deferred.
- `C_Mz` — no such field; hub torque is `C_Q` (already exposed).
- Whole-aircraft total force/moment (`AircraftState.forces`, dimensional) — different quantity.
- Python API — already exposes them (`python.d:2567-2568`).
